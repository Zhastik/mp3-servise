# Архитектура ВОЛНЫ

Проект — модульный монолит на FastAPI и SQLAlchemy. Каждый бизнес-модуль содержит свой HTTP-контракт, сценарии, запросы к базе и модели. Файловая обработка реализована инфраструктурными адаптерами. База данных и хранилище общие; имена таблиц и публичные URL сохранены.

## Карта проекта

```text
app/
  main.py                  # create_app: сборка приложения
  lifespan.py              # запуск и остановка фоновой очистки
  api/
    router.py              # регистрация модульных роутеров и префиксов
    exception_handlers.py  # ApplicationError -> HTTP
    responses.py           # HTTP Range/HEAD для аудио
    system.py              # /health и /api/status
  core/
    config.py              # настройки, пути, ключ
    database.py            # engine, session factory, Base, DB bootstrap
    db_depends.py          # сессия на запрос и страховочный rollback
    errors.py              # ошибки прикладного слоя
    transactions.py        # commit/rollback на границе сценария
    middleware.py          # лимиты тела, Origin, защитные заголовки
    time.py                # UTC-время
  modules/
    auth/                  # регистрация, сессии, вход, выход, CSRF
    users/                 # модель и репозиторий пользователя
    tracks/                # каталог, квоты, загрузка, изменение, удаление
    favorites/             # избранное
    playlists/             # личные плейлисты и связи с треками
  infrastructure/media/
    antivirus.py           # ClamAV CLI / INSTREAM
    transcoder.py          # MP3 и FFmpeg
    storage.py             # Fernet и файловая система
    processor.py           # конвейер проверки и обработки
    models.py              # запись очереди удаления
    repository.py          # доступ к очереди в БД
    cleanup.py             # повторное удаление файлов
    dependencies.py        # сборка адаптеров
  models.py                # только реестр моделей для Alembic
  static/                  # HTML, CSS, браузерный плеер
alembic/                   # версии схемы БД
tests/                     # интеграция, миграции, границы слоёв
```

## Устройство бизнес-модуля

| Файл | Ответственность |
| --- | --- |
| `routers.py` | URL, метод, входные HTTP-параметры, вызов сервиса, HTTP-ответ |
| `schemas.py` | Pydantic-схемы входа и выхода; закрытые поля хранилища наружу не выдаются |
| `dependencies.py` | Сборка сервиса и внедрение зависимостей через FastAPI |
| `service.py` | Сценарии, права владельца, ограничения, координация операций, транзакции |
| `repository.py` | SQLAlchemy-запросы и сохранение сущностей; без commit/rollback |
| `models.py` | ORM-таблицы данного модуля |

Модуль пользователей не имеет отдельных публичных CRUD-эндпойнтов: его операции используются авторизацией и проверкой квот. В избранном нет схемы тела запроса: операция определяется URL и HTTP-методом. Парольные функции находятся в `auth/security.py`, HTTP-проверки сессии и CSRF — в `auth/dependencies.py`.

## Направление зависимостей

```text
HTTP router -> service -> repository -> database
                  |
                  +----> media ports <---- infrastructure adapters
```

Роутеры не обращаются к ORM и не выполняют проверки квот или владения. Сервисы и репозитории не импортируют FastAPI, Request, Response или HTTPException. Сервисы выбрасывают `ApplicationError`; единый обработчик превращает её в прежний ответ `{"detail": "..."}` с нужным статусом.

Репозитории возвращают модели или выборки и могут выполнять flush, но не завершают транзакцию. Простые сценарии используют `core.transactions.transaction`: успех завершает commit, исключение любого вида вызывает rollback. Auth-зависимость и модульный сервис используют одну сессию запроса через `get_db`.

Связанные модули используют конкретные репозитории друг друга для чтения и удаления связей в общей транзакции. Универсальный CRUD-репозиторий и дублирующие слои не добавлены. Порты нужны на внешней границе: антивирус, обработчик, файловое хранилище и очередь удаления внедряются в сервис треков через `tracks/ports.py` и его фабрику зависимостей.

## Пример: загрузка трека

1. `tracks/routers.py` принимает `POST /api/tracks`, форму и файл, получает текущего пользователя.
2. `TrackService.upload` ограничивает параллельные загрузки, блокирует строку пользователя и проверяет квоту через репозитории.
3. `AudioProcessor` проверяет входной файл антивирусом, разбирает MP3, перекодирует его, повторно сканирует и передаёт шифрованному хранилищу.
4. Репозиторий создаёт трек, сервис завершает транзакцию. В ответ возвращается `TrackRead`, без файлового пути и внутренних полей.
5. При неудаче транзакция откатывается, созданный файл удаляется. Если удаление временно невозможно, путь ставится в постоянную очередь. Во время commit отмена запроса не должна удалять файл, уже принадлежащий сохранённому треку.

Удаление трека и постановка его файла в очередь выполняются в одной транзакции. Фоновая очистка повторяет файловые операции после commit.

## Как добавить функцию

Добавьте входную/выходную схему, запрос репозитория и сценарий сервиса. Роутер должен только принять параметры и вызвать сценарий. Новый модуль подключается в `api/router.py`; его модели добавляются в реестр `app/models.py`. Если меняется схема БД, создаётся отдельная миграция Alembic. Если появляется внешний ресурс, его интерфейс определяется портом и реализуется адаптером.

## Проверка границ

`tests/test_architecture.py` проверяет импорты слоёв, отсутствие SQL в роутерах, отсутствие управления транзакциями в репозиториях и использование портов для медиа. Интеграционные тесты отдельно проверяют поведение API. Структурный рефакторинг не изменяет схему БД, поэтому новой миграции для него нет.
